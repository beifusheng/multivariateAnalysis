## 1. 这个模块替用户回答什么

一句话：**处理/环境变量 X 对响应矩阵 Y 的影响，有多少是直接的、有多少是经过中介 M 传过去的。**

输入三张同序样本表（与 GMR⁴ 同构，行=样本，列=变量，都允许多列）：

| 记号 | 形状 | 业务含义（举例） |
| --- | --- | --- |
| `X` | n × p | 环境因子 / 处理强度（解释变量） |
| `M` | n × k | 中介：功能性状、中间群落指标、生理指标 |
| `Y` | n × q | 响应矩阵：物种丰度 / 基因丰度 / 多指标结局 |

产出四样东西，都必须能在页面上指着说人话：

1. **效应三分**：直接效应 B、间接（中介）效应 A·C 的对应项、总效应 = 直接 + 间接，
   每个都给后验中位数与 95% 可信区间（HDI）。
2. **RDA 式方差分解**：Y 的总变异拆成「X 直接解释」「经 M 传来」「残差」三块，逐典范轴给出。
3. **收敛诊断**：链数、迭代数、每个待量参数的 split-R̂ 与 ESS。**不达标必须开口**，
   不许把数摆出来就走（这是本项目对"看起来能跑"的一贯态度）。
4. **模型比较**：WAIC（不是 BAIC，见 §6）。

## 2. 模型（我定的形式）

逐列高斯线性，系数弱信息正态先验，方差逆伽马共轭 —— 整套有闭式条件后验，
所以能用**手写 Gibbs** 跑，不需要任何采样器依赖：

```
标准化：Xc, Mc, Yc  = 按列中心化并按列标准差缩放（sd=0 的列剔除并报 diagnostic）

M 侧：  m_k = Xc γ_k + e_k ,  e_k ~ N(0, σ_k² I)
Y 侧：  y_q = Xc β_q + Mc ω_q + ε_q ,  ε_q ~ N(0, τ_q² I)

先验：  γ_k, β_q, ω_q ~ N(0, λ⁻¹ I)，λ = 1（标准化尺度上，等价于"1 个 SD 的效应算大"）
       σ_k², τ_q² ~ Inv-Gamma(1e-3, 1e-3)   # 近无信息
```

派生量（逐 (预测 j, 响应 q) 对）：

```
间接效应 ind[j,q]  = Σ_k γ[j,k] · ω[k,q]
直接效应 dir[j,q]  = β[j,q]
总效应   tot[j,q]  = dir + ind
```

**为什么这条恒等式在本设定下精确成立**：把 `m_k = Xγ_k + e_k` 代回 Y 的方程，
得 `y_q = X(β_q + Σ_k γ_k ω_{k,q}) + (e 项) + ε_q`，括号里就是总效应的系数。
这个代数关系就是 `verify` 脚本要逐条核对的东西，不是"差不多就行"。

多响应（q>1）与多中介（k>1）都天然支持：逐列 Gibbs 之间条件独立，可直接向量化。

## 3. 采样器（我定的实现方式）

- 共轭条件后验：给定方差，系数是 `N((X'X + λI)⁻¹X'y, σ²(X'X+λI)⁻¹)`；
  给定系数，方差是 Inv-Gamma。矩阵求逆一律走 `chol` / `backsolve`（项目硬规定，不许 `solve` 裸用）。
- 4 条链，**独立种子**（seed, seed+1, …），每条 burn-in = iterations/2。
- 抽样用 `MASS::mvrnorm`；正态随机数只用 base `rnorm`，不引入任何 RNG 包。
- 同输入必同输出：seed 决定一切，两次跑逐字节相同（回归网靠这条）。
- split-R̂：链内对半切，`sqrt((W(1+df/n)+B)/V)`（Gelman–Rubin 保守版，小样本修正）。
- ESS：由链内自相关初始正序和估计，按链求和后取最小值作为该参数的 ESS。
- 阈值（我定）：`R̂ > 1.05` 或 `ESS < 400` 就写进 diagnostics 并在页面上亮警告。
- 性能兜底：n·(p+k+q) 超过阈值时提示用户减少迭代数；超时上限沿用 30min。

## 4. 频率派锚点（拿真实现对齐，不是自说自话）

| 要验的东西 | 锚点 |
| --- | --- |
| RDA 每轴解释量、整体 adj.R² | `vegan::rda` + `vegan::RsquareAdj` |
| 系数后验均值 ≈ OLS 估计 | 同数据 `lm()`（大样本、近无信息先验下必须靠近） |
| 总效应 = 直接 + 间接 | 上面 §2 的代数恒等式 + 数值一致性双查 |
| 中介乘积的抽样分布形状 | 无偏 Bootstrap 乘积分布对照（`boot` 在）—— 只比方向与量级，不比小数位 |

`coda` / `rstan` / `jags` 都不许出现：打包侧删过 jags.dll，运行时不许依赖外部二进制

## 9. Spike 结果（2026-11-20，两份 throwaway 脚本，不进版本库）

### 已经站住的

- **恒等式 `tot = dir + ind`**：数值残差 `5.55e-17`（机器精度）。这条以后进 `verify_era_engine.R`。
- **与频率派对齐**：`vegan::rda(Y ~ X + M)` 约束惯量/总惯量 = 0.5765，我的 `R²(XM)` = 0.5765；
  `rda(Y ~ X)` 0.4545 vs 我的 0.4545 —— 方差分解这半边**有真锚点**，不是自说自话。
  三段式（X 独有 / X∩M / M 独有 / 残差）合计 = 1.000000。
- **后验均值 ≈ OLS**：dir 最大偏差 0.0031、ind 0.0036、tot 0.0013（近无信息先验 + n=300 应有行为）。
- **确定性**：同 seed 两次跑差 = `0e+00`；换 seed 结果不同 ✓。

### 踩到的四颗地雷（全部已拆，并且全部是**我自己的检查**错了，不是模型错了）

1. **split-R̂ 实现是坏的**，被自检抓出来：我把 `B` 写成了 `nn * var(rowMeans(H))`
   （行均值 = 把各链按位平均，方差≈W/M），正确的是 `nn * var(colMeans(H))`。
   错版的数学直接给出 `R̂ ≈ sqrt(1 + (M-1)/M · n/(2n)) ≈ 1.06` 的**常数偏高**，
   而且对链间差异完全不敏感 —— 所以 spike 里“1.128 / 1.06 且不随迭代下降”全是假的。
   修后自检：iid → 1.0004；逐链偏移 0.5σ → 1.167；随机游走 → 3.27；
   重测采样器：**2000 迭代就已经 R̂(ind) 1.0005 / R̂(dir) 1.0025**，24000 迭代 1.0003/1.0000。
   → 采样器一直没问题，有问题的是量它的尺子。
2. **R 的数组乘法不广播尾维 1**：`(S,p,1) * (S,1,q)` 直接报「非整合陈列」。
   间接效应必须逐 draws 做 `p×k %*% k×q`（或 `outer`），别拿 numpy 直觉写 R。
3. **原始尺度真值 vs 标准化尺度后验**：spike#2 报“覆盖率 ind 37.5%”——
   数据用 `Gtrue/Btrue/Wtrue`（原始尺度）生成，模型却拟合在 z-score 尺度上，
   两者差着 sd 比。把真值换算到标准化尺度（sweep 的 margin 写错还会静默得错数，
   行=预测维、列=方程目标维）后重测：
   **ind 95.0% / dir 92.5% / tot 97.5%（名义 95%，40 格，MC 误差≈±7pt）**，
   平均半宽 ind 0.085 / dir 0.097 / tot 0.092。
   附带教训：**单次数据的覆盖率不是判据**（覆盖率是跨重复的频率性质），
   而且要比的是同尺度的同一个量 —— 上一轮“HDI 只框住 8/12”同样是这个错。

4. **后验均值的聚合方向又错了同一个地方**：`rowMeans` 是“逐行把列平均”（把 4 个格子
   平成了一个数 0.1156），要的是 `colMeans`。错版报出“RMSE 0.369”而覆盖率 95%、
   半宽 0.085 —— **三个数互相矛盾才把它抓出来的**。注意这已经是本 spike 里
   第二次 `row/colMeans` 同型错误（第一次是 split-R̂ 里的 B）。

### 修正后的最终实测（.tmp_era_spike3.R，n=200、p=2、k=1、q=2）

| 检查 | 结果 |
| --- | --- |
| 经验覆盖率（名义 95%，REP=10 共 40 格，MC 误差≈±7pt） | ind 95.0% / dir 92.5% / tot 97.5% ✓ |
| 后验均值 vs 标准化真值 RMSE | 0.039 – 0.052（与半宽 0.07–0.13 同量级）✓ |

### 比单个 bug 更值钱的三条测试设计结论

1. **单向阈值断言拦不住坏尺子**。`rowMeans` 版的 R̂ 常数偏高到 ≈1.055，于是
   "脏了必须报 R̂>1.05" 的 T2 照样通过。要围死一个坏实现，必须同时有：
   干净时不许红（T1/T10）、脏了必须红（T2/T3）、**且报警能定位到具体哪一列**
   （T12：只有第 3 列脏，就只许第 3 列报）。
2. **判据要打在我们要验的那一层**。`quantile(na.rm = FALSE)` 遇到 NA 自己就报错，
   所以"报错了吗"这个判据完全没碰到我那层守卫；改成断言**报错文案出自我们**之后，
   删掉守卫才红。否则一个谁都没维护的默认行为会一直替测试"打掩护"。
3. **"该红的没红"本身就是缺陷信号**。本轮两次靠它发现问题：一次是 python 替换没落地
   （`anyNA` 还剩一处），一次是变异被另一个变种的报错掩盖。

## 15. 上线后的第一个真发现：生产调用形态我从来没走过

四个模块都"上线"了，但我所有测试都用**仓库内相对路径 + cwd=仓库根**去起 Rscript，
而 `public/electron/main.js` 实际是 `spawn(rPath, [绝对脚本路径, 输入, 输出, 错误])`
且**不设 cwd**。按真实形态试一次，立刻撞出一个真 bug：

输入 `X2 = 2·X1`（列成比例）时，引擎报的是
**「需要TRUE/FALSE值的地方不可以用缺少值」** —— 一句没人看得懂的 R 内部错误。

链路查清：秩亏时 `lm.fit()$coefficients` 给被挤掉的系数填 **NA**，我原来的写法
只在 `rcond < 1e-10` 时**加一条 diagnostics 然后继续跑**，NA 一路流到
`if (dev_dir > tol || dev_ind > tol)` 才炸。也就是说：
**识别问题被我当成了软警告处理，最后以内部错误的形式暴雷。**

### 改了什么

1. **两级策略**：完全秩亏（`< 1e-10`）= 硬停，且按种类分别点名
   （X 内部成比例 / M 内部重复 / M 能被 X 完全解释 —— 三种的解决办法不一样）；
   接近秩亏（`< 1e-6`）= 开口但继续。特别把「第二列 = 第一列 + 常数也算完全共线」
   写进文案，因为标准化会先减均值 —— 这一种最容易漏。
2. **检查挪到采样之前**：先拒坏输入，别先花 60 秒再拒绝。
3. **NA 不再往下流**：`ols_full/ols_g` 出来先 `anyNA()` 检查，命中就报
   "内部校验失败：闭式 OLS 含 NA，说明秩亏但没被拦住 —— 请报告这组输入"；
   偏差比较也用 `max(..., na.rm = TRUE)` 并检查 `is.finite`（防御纵深）。
4. **`source` 失败不再是裸退出**：这段解析在主 `tryCatch` **之前**，上一版直接 `stop()`，
   于是打包环境一旦找不到兄弟文件，进程带着 R 内部错误退出、**连 error 文件都不创建**，
   前端只能显示"执行失败"。现在自己写清 error 文件再以非零码退出。

## 16. 用户报的导出故障：根因是我的测试套件在污染他的 dev 缓存

用户反馈：Bayesian ERA 里**导出模板点了没反应**，导出结果报
`Failed to fetch dynamically imported module: http://localhost:8080/node_modules/.vite/deps/xlsx.js?v=70588e87`。

调查过程（两次假设都被实测否掉，记录在这里以免下次再靠猜）：

1. **假设一**「Vite 没预打包 xlsx，加 `optimizeDeps.include` 就好」→ A/B 打掉：
   把 include 删掉再起服务，`xlsx` 照样出现在 optimized 里（Vite 的扫描器会静态扫到
   动态 import）。所以那个配置改动是**治错了地方**，已撤销，不留"顺手加的改动"。
2. **假设二**「浏览器拿着过期的 `?v=` 哈希」→ 直接打 URL 打掉：正确哈希、故意写错的哈希、
   不带哈希，三种都返回 200。`?v=` 在这条路径上不门控内容。
3. **真根因**：`test_*_view.mjs` / `test_*_render.mjs` / `test_import_shell.mjs` 一共
   **8 个套件**会 `createServer({ root: FRONTEND, ... })`，而 vite 的 `cacheDir` 默认值就是
   `frontend/node_modules/.vite` —— **与开发者正在跑的 `npm run dev` 是同一份缓存**。
   我每跑一轮套件就把它改写一遍（还看到 `deps_temp_*` 残留、browserHash 从
   `d0123a31` 变成 `1049b826`）。用户浏览器里已加载的页面持有旧引用，
   点导出时那次动态 import 就取不到文件。

**是我把他跑坏的吗：是。** 不是产品代码的问题，也不是 ERA 特有的问题。

## 17. 第二条报修：我上一轮的提示给错了，而且我的断言是假的

### 同时暴露出我新写的断言是"为错理由而绿"（第四次）

const NL = String.fromCharCode(10);
const methodBody = (src, name) => {

};
